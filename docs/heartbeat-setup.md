# iStoreOS 模组自检与正常心跳

此阶段已实现发送端；ECS 接收和 Bark 超时报警由独立仓库建设。本机不会自行冒充远端报警。
未准备好符合 [v1 协议](heartbeat-protocol.md) 的 HTTPS 接收器前保持上报关闭。

## 自检判定

启动后立即检查，随后每分钟检查，不需要启用心跳就能查看自检：

- 当前 AT 通信、SIM READY、蜂窝本地/漫游注册。
- 本轮查询移动数据自动拨号关闭，且短信专用 guard 已核验关闭。
- 短信同步最近 150 秒内成功，且没有当前读取或写入归档错误。
- SQLite 只读查询可用；本轮检查不超过 45 秒。

未初始化、忙碌超时、快照过期或任一项异常都不是正常。健康检查不测试真实短信发送，
不改模组数据设置，也不替代运营商短信服务端的端到端验证。信号百分比不单独决定正常。
USB 断开或模块恢复期间可暂时异常；下一分钟重查。数据 guard 仍由既有逻辑每 30 秒核验。

## 网页配置

通过现有 SSH 隧道打开 `http://127.0.0.1:7676/`，找到“模组自检与心跳”。
Mac 旧服务已禁用时可使用：

```sh
ssh -N -L 7676:127.0.0.1:7676 root@192.168.100.1
```

1. 查看当前自检各项及完成时间，可点击“立即自检”。
2. 填写设备 ID、展示名称、完整 HTTPS 接收地址（路径固定 `/v1/heartbeat`）。
3. 使用独立随机密钥，例如在管理电脑运行 `openssl rand -hex 32`，将同一密钥安全配置到
   本机和 ECS。不要复用 Bark key/TG Token，也不要把密钥发到聊天或放进 Git。
4. 周期默认 600 秒（10 分钟）；接收端须配置同一周期和 2 个超时周期。
5. 勾选启用并保存。立即进行自检；正常时立即上报一次，之后按周期上报。
6. “自检并上报”仍有健康门禁；HTTP 200 且 `{"ok":true}` 才标记成功。

保存后密码框清空；以后密钥留空保留旧值。定时刷新仅刷新状态，不覆盖正在编辑的字段。
重新配置/禁用会取消并等待旧发送工作停止；保存失败不偷偷启用未保存配置。
周期修改须同步修改 ECS，否则接收端会拒绝心跳。

## 配置与隐私

默认 `<dataDir>/heartbeat.json`，目录必须由运行用户所有且为 0700，文件为 0600。
iStoreOS 的 `/etc/vohive-sms-forward/data/` 已满足要求。采用 root 进程时文件应归 root；
其他启动方式请核对目录/文件所有者，不要混用 sudo 改变所有者。
配置读取失败仍保留短信服务与本地自检，但不上报，页面显示 config_invalid。

```json
{
  "enabled": false,
  "device_id": "router-1",
  "name": "iStoreOS",
  "endpoint": "https://ecs.example/v1/heartbeat",
  "secret": "在网页填写独立生成的64字符hex密钥",
  "interval_seconds": 600
}
```

上面是字段说明，不是可直接运行的凭据。文件由网页原子保存，不需要修改 UCI/procd。
升级保留数据目录；不要把该目录放 `/tmp`。没有配置文件时上报默认关闭。
API 的 `/api/heartbeat` 只返回脱敏设置、最后自检、最后尝试/成功及固定错误分类。
发送失败不会记录接收地址的认证信息，也不会上传短信或 SIM 身份。

## 故障诊断与验收边界

- self_check_failed：检查各项，尤其 SIM 注册、归档错误、guard 是否 off；不强行报平安。
- delivery_failed：核对 HTTPS 证书、接收路径、密钥、设备 ID、周期、应答及双端校时。
- config_invalid：修复配置文件结构、权限、所有者或网页字段。
- durability_unconfirmed：配置已生效但目录落盘同步未确认，应检查存储后重新保存。

正常短信功能不因 ECS 不在线而停止。心跳 worker 不发送 Bark 失联报警；报警必须由
ECS 独立进程产生，才能覆盖 iStoreOS 断网、断电或程序停止。ECS 自身失效仍需外部监控。

测试接收器的通过证明发送协议，不等价于 ECS 实机上线和20分钟失联报警验收。
